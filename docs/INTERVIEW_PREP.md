## 1️⃣ Bitpanda — Software Engineer Golang

### 背景
- 加密货币交易平台，需要高吞吐量钱包基础设施
- 技术栈：Go + Kubernetes + 分布式系统
- 你的相关经验：VeChain 3 年 / 钱包架构 / BaaS 平台

### 技术问题

#### Go 语言深度
```
1. 【基础】解释 Go 的 goroutine 和 thread 的区别，为什么 goroutine 更适合高并发？
   → 答题要点: 轻量级、调度器、M:N 模型、context 管理

2. 【中等】你在 VeChain 的钱包系统中如何处理并发的私钥管理？
   → 答题要点: 使用 channels / sync.Mutex / 原子操作 / race condition 检测

3. 【中等】Go 的垃圾回收机制对高频交易系统有什么影响？如何优化？
   → 答题要点: STW、GC pause、内存池、对象复用、GOGC 调参

4. 【困难】设计一个高性能的 Go 连接池，如何处理连接失败和超时？
   → 答题要点: 心跳检测、retry 策略、backoff、熔断器模式
```

#### 区块链 & 钱包
```
5. 【基础】什么是 ECDSA？它在钱包中的作用是什么？
   → 答题要点: 非对称加密、签名验证、私钥保管、确定性

6. 【中等】在你的 VeChain BaaS 平台中，如何安全地存储和使用客户的私钥？
   → 答题要点: HSM / KMS / 冷钱包 / 热钱包分离 / SlowMist 审计

7. 【中等】Bitpanda 平台需要实时处理数千交易，你如何设计一个高可用的钱包系统？
   → 答题要点: 分片 / 缓存层 / 数据库分区 / 异步处理
```

#### 系统设计
```
8. 【困难】设计一个支持 100K TPS 的区块链钱包系统（Bitpanda 规模）
   - 核心问题：交易吞吐量 / 一致性 / 容错性 / 成本
   - 答题框架：
     a. 需求澄清（TPS / 延迟 / 精度）
     b. 高层架构（API Gateway / 消息队列 / 数据库）
     c. 可扩展性（水平扩展 / 分片）
     d. 可靠性（冗余 / 故障转移 / 审计日志）

9. 【困难】如何防止双花攻击和交易重放？
   → 答题要点: nonce / 签名验证 / 状态管理 / 原子性
```

### 行为问题
```

    → 为什么重要：衡量领导力和实际交付能力

## 2️⃣ Zscaler — Staff Software Engineer AI Security (⭐ 最难)

### 背景
- 全球网络安全领导者，Staff 级职位（顶级工程师）
- 技术栈：Go + Rust + Python + AI/ML
- 你的相关经验：FI-Agent (AI/Agent 系统) / 20 年后端经验 / 分布式系统
- **风险**: AI Security ≠ 区块链安全 (需要主动弥补差距)

### 技术问题

#### AI Security 深度
```
1. 【困难】解释什么是"对抗攻击"(Adversarial Attack)，举例说明。
   → 答题要点：
      - 定义：精心设计的输入让 ML 模型做出错误决策
      - 例子：图像识别里添加噪声 / NLP 里的 prompt injection
      - 防御：对抗训练 / 输入验证 / 模型解释性

2. 【困难】你的 FI-Agent 系统如何防止被 LLM 模型中毒？
   → 答题要点：
      - 数据验证（来源检查）
      - 模型隔离（沙箱环境）
      - 监控异常（outlier detection）
      - RAG 系统的风险（只用可信数据源）

3. 【困难】在 Zscaler 这样的安全产品中，如何使用 AI 检测零日漏洞？
   → 答题要点：
      - 异常检测（行为分析）
      - 特征工程（网络流量 / 文件行为）
      - 模型选择（Random Forest / XGBoost / Deep Learning）
      - 误报率权衡
```

#### Rust 系统编程
```
4. 【困难】Rust 的所有权系统如何帮助防止安全漏洞？举例说明。
   → 答题要点：
      - 内存安全：no buffer overflow / use-after-free
      - 线程安全：Send + Sync traits
      - 例子：Rust 写网络驱动时的内存保护 vs C 的风险

5. 【中等】你在 Go 中如何实现类似 Rust 所有权的内存安全机制？
   → 答题要点：
      - 使用 interface{} 不检查类型安全
      - Go 的 GC 简化了内存管理但引入 GC pause
      - 权衡：性能 vs 安全
```

#### 系统设计
```
6. 【困难】设计一个实时恶意软件检测系统
   - 核心问题：检测延迟 < 100ms / 误报率 < 0.1% / 支持 1M+ 端点
   - 答题框架：
     a. 数据收集（agent + 上报）
     b. 特征提取（行为 / 静态分析）
     c. ML 推理（轻量模型 + 在线学习）
     d. 决策（实时阻止 / 隔离）
     e. 反馈循环（新样本 → 模型更新）

7. 【困难】在公有云环境中，如何构建安全的 AI 推理服务？
   → 答题要点：
      - 模型加密（TEE / FHE）
      - 推理隔离（容器 / 虚拟机）
      - 日志审计
```

### 行为问题
```
8. 【关键】Staff 级职位：你的技术愿景是什么？如何影响组织方向？
   → 为什么重要：衡量策略思维和影响力

## 🎓 通用面试技巧

### 关键原则
```
1. STAR 方法讲故事
   Situation → Task → Action → Result
   例：我在 VeChain 面临的是...（S）
       我的职责是...（T）
       我采取的行动是...（A）
       结果是...（R）

2. 量化你的成就
   不说："我优化了系统"
   要说："我优化了 API 延迟从 500ms 到 50ms，QPS 提升 10 倍"

3. 诚实面对劣势
   不要隐瞒"我没做过 Rust" or "AI Security 不是我的专长"
   要说："我在 X 领域经验不足，但我的学习能力很强，
          我在 Y 上的经验有迁移价值"

4. 反问问题很重要
   表明你在认真思考这份工作
   避免："工作地点在哪？" 之类的基本问题
   改问："你认为这个职位最大的技术挑战是什么？"
```

## 📊 成功的面试的标志

✅ **你做对了**

- 夸大其词或撒谎
- 沉默或"我不知道"（应该说"我可以怎样找到答案"）

- 看起来不感兴趣
